# 金标准评估集说明

## 设计原则

1. **锚定内容片段，不锚定 chunk id。** gold 里的 `anchor` 是从原文复制的 verbatim 片段。chunk id 由切分策略决定——每次调 chunk 大小，id 全变，评估集就废了；而 anchor 文本与切分策略无关，评估脚本在评测时用子串匹配把 anchor 映射到当前 chunk，评估集因此可以跨切分策略稳定复用。
2. **必须包含拒答题（must_refuse=true）。** 安全敏感场景的评估集里，"该拒答时拒答"和"该答对"同等重要。q038 是陷阱题：乙酸乙酯的沸点模型大概率"知道"，但必须拒答——否则说明系统在用内置知识冒充检索结果，这正是本项目第一性原则要防的事。
3. **包含错误前提题（false_premise）。** q041 的前提是假的，考察系统是否纠正前提，而不是顺着用户的错误前提编故事。

## 题型分布（42 题）

| category | 数量 | 考察点 |
|---|---|---|
| factoid_number | 5 | 编号、数值抽取（CAS、沸点） |
| table_query | 1 | 表格检索完整性 |
| sop_condition | 6 | 操作条件类（安全核心） |
| safety | 5 | SDS 安全知识 |
| patent_condition / report_condition | 8 | 条件与数字 |
| explanation | 1 | 因果解释 |
| recommendation | 4 | 跨段归纳建议 |
| cross_doc | 4 | 跨文档关联 |

| must_refuse | 4 | 拒答能力 |
| false_premise | 1 | 前提纠错 |

## 诚实声明

语料为练习用合成文档（基于公开化学常识编写，专利为模拟文本），非真实企业内部资料。真实项目中评估集问题必须来自真实用户。合成语料的问题是"出题人知道答案在哪"，会高估系统表现——练手可用，但需在结论中说明这一偏差。

## 命中判定规则（评估脚本实现时遵循）

- 命中 = gold 中**至少一个** anchor 被切分后所在 chunk 的文本包含（子串匹配），且该 chunk 出现在该问题的检索结果 top-k 中。
- Recall@k = 命中问题数 / 总问题数（must_refuse 题不计入 Recall，单独统计拒答准确率）。
