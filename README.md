# 化工生产知识问答系统（RAG）

面向化工安全敏感场景的检索增强问答。核心约束不是"答得准"，而是 **「无依据必须拒答、每个结论必须能指到原文」**。

---

## 为什么做

化工资料分散在 SOP、SDS、专利、实验报告里，同一物质有中英文和部门内部多种叫法，作业标准还有作废版本——检索长期靠人肉。

更关键的是：**这是安全敏感场景。** 模型编造一个反应条件，轻则停车停产，重则出事故。所以这个项目从第一行代码起，就把「拒答」和「可溯源」当成一级需求，而不是事后补丁。

---

## 架构

```
离线
  corpus_final/*.pdf|*.txt
        │
        ├─ pdfplumber：表格区域识别与排除（避免 CAS 号被切碎 / 表格与正文双份入库）
        ├─ 章节语义切分 → chunks.json
        └─ bge-small-zh-v1.5（512 维）→ Milvus 集合

在线
  question
     │
     ├─ rewrite（同义词/术语归一；消融后默认关闭，开关保留）
     ├─ 稠密召回 top-N  ─┐
     ├─ BM25 召回  top-N ─┴─ RRF 融合（k=60）→ bge-reranker-base 交叉重排
     ├─ 拒答闸门（无足够依据 → 直接拒答）
     ├─ DeepSeek 生成（强制 [n] 引用）
     └─ 指针回对：每条断言回查所引片段 → 引用准确率
```

---

## 关键设计决策

每条都写清「候选 → 代价 → 为什么选这个」。

**1. 评估集用 anchor 原文片段锚定，而不是 chunk id**
chunk id 由切分策略决定，改一次切分全变，评估集就废了；anchor 与切分无关，评测时用子串匹配映射到当前 chunk，因此可以跨切分策略复用。代价是匹配要处理空白归一化。

**2. 稠密 + BM25 双路召回，用 RRF 融合**
稠密擅长语义（"加氢还原"≈"hydrogenation"），但对精确标识符无能——`GB 50160-2008 第 5.2.2 条`、CAS 号在向量空间里没有区分度。BM25 反之。
融合用 RRF（`Σ 1/(k+rank)`）而不是加权求和：两路分数量纲不可比，归一化本身又会引入超参。`k=60` 是原论文经验值，作用是压平头部优势。

**3. 重排用 Cross-Encoder**
bi-encoder 的 query 与 doc 没有交互；Cross-Encoder 把 `[query, doc]` 拼在一起送进模型，补上词级交互。代价是必须实时计算，只能对少量候选做。

**4. 拒答做两层，且承认哪层在起作用**
层一：检索分数闸门；层二：prompt 约束 + 指针回对。
实测层二已经 5/5 全过，层一阈值未标定即放弃——这是刻意的过度设计裁剪，风险（换更自信的模型时层二失效）记录在案。

**5. judge 异源 + 人工标定**
生成用 DeepSeek，裁判用 Kimi，避免同源偏好。但异源不等于无偏——抽 43 条人工裁决标定，发现裁判系统性偏严（closed-book 侧 33%、RAG 侧 57%），修正后 headline 从 2.92% → 1.25%。

## 评测结果

评估集：**43 题**（38 道计分题 + 5 道必拒答题；其中含 1 道错误前提陷阱题 q041）。

### 检索层（38 计分题，top_k=3）

| 配置 | recall@3 | MRR@3 |
|---|---|---|
| 纯向量基线 | 0.684（26/38） | 0.561 |
| + BM25 + RRF | 0.789（30/38） | 0.697 |
| + Cross-Encoder 重排 | **0.895（34/38）** | **0.833** |

> 重排的收益集中在 @1/@3（@1 从 24 提到 30 题），**@10 一分未变**——重排不改召回，只改排序。

### 生成层

| 指标 | 结果 |
|---|---|
| 断言级幻觉率（RAG） | 2.92%（裁判标定后 **1.25%**） |
| 断言级幻觉率（closed-book 裸生成，同裁判同题） | 28.26% |
| 引用指针准确率 | 96.15%（38 题 / 104 指针） |
| 必拒答题正确拒答 | **5/5** |

> closed-book 对照是最有说服力的一组数：同一批题、同一个裁判，无检索 28.26% → 有 RAG 2.92%，约 9.7 倍压制。

## 快速开始

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 1) 建 chunks（需要 corpus_final/ 下放语料）
python get_chunks.py

# 2) 建向量库（本地 Milvus 或 Standalone，地址见环境变量）
python vectorize_and_store.py

# 3) 提问
python answer.py "格氏试剂制备时的加料顺序和温度要求？"
```

环境变量示例见 `.env.example`（需自备 LLM / Embedding 的 API Key）。

## 已知局限

以下问题已在评测中定位，尚未修复，按影响排序。

1. **语料是合成文档**（基于公开化学常识编写，专利为模拟文本）。出题人知道答案在哪，会系统性高估召回——真实项目里评估集必须来自真实用户提问。
2. **没做 chunk size 消融**。切分是影响最大的变量，我优先做了重排和改写，这是欠账。
3. **表格行不自包含**。q002「二氯甲烷沸点」在 @5 仍漏检，原因是表格行脱离表头后没有"沸点"二字。
4. **`rank_bm25` 是全内存索引**，几万份文档时不可用，需换 ES 或 Milvus sparse。
5. **复合问题未分解**。q022「该专利的催化剂是什么、镍负载量多少」在三种配置的 @5 全部漏检——单 query 向量把两个意图平均掉了。
